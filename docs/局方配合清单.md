# 正式上线 · 局方需配合事项与材料清单

（2026-09-24 整理；对应系统版本 1.2.0 / 第十三轮收口。★ 为不做则不能上线的硬前置。）

## 一、环境与运维（信息科/运维）

| # | 事项 | 具体要求 | 谁 |
|---|---|---|---|
| ★1 | 境内部署环境 | 局内网服务器或境内已备案云主机；Ubuntu 22.04+，2 核 4G 起，40G 盘；能装 Docker。现香港试运行机只能放虚构数据 | 信息科 |
| ★2 | 访问地址与证书 | 内网：一个固定 IP 或内网域名；公网：备案域名 + 放行 80/443，SSH 仅限运维 IP | 信息科 |
| ★3 | 三个秘密值 | 由局方运维生成并保管：`DB_PASSWORD`、`JWT_SECRET`（≥48 位随机）、`ADMIN_INIT_PASSWORD`（管理员初始口令，首次登录强制改）。不要沿用试运行机的值 | 运维 |
| 4 | 告警渠道 | 一个企业微信/钉钉/飞书群机器人 webhook（填 `.env` 的 `ALERT_WEBHOOK`），以及 1–2 名收告警的运维联系人 | 运维 |
| 5 | 备份外拷 | 系统每日 03:30 自动备份到本机（保留 14 份）；局方需提供异地/NAS 位置及拷贝方式，本机备份不算灾备 | 运维 |
| 6 | 附件存储方式 | 决定 `attachment_storage`：库内（默认，够用）或外置目录（执法音像多、单件 >10MB 时必须外置，需给独立盘） | 信息科 |
| 7 | 等保/信创口径 | 明确是否要求国产数据库（金仓/达梦）。现为 PostgreSQL；信创适配摸底见 `docs/信创适配摸底.md`，若要求需另排期 | 信息科 |
| 8 | 上线窗口与培训 | 上线日期、停机窗口、培训场次（办案员 / 法制 / 负责人 / 管理员各一场） | 办公室 |

## 二、机构与人员数据（办公室/人事）

机构和人员由管理员在「机构管理」和「用户管理」中按审核名册配置。机构参数和执法证可使用 `tools/init-bureau.py`，人员账号和部门目录由管理员先维护。执法证 CSV 可按顺序填写「姓名、执法证号、部门、有效期（YYYY-MM-DD）、法律职业资格（0/1）、登录账号」。填写登录账号时，工具核对姓名、所属机构、岗位及现有证号绑定。先运行 `python tools/init-bureau.py --enforcers 执法证.csv --dry-run` 预检，再在维护窗口执行写入。

| # | 材料 | 字段 |
|---|---|---|
| ★1 | 机构信息 | 全称、简称、举报电话；**案号前缀**（如"X医保案"→ X医保案〔2026〕1号）、**处罚决定书文号前缀**（如"X医保罚"） |
| ★2 | 部门列表 | 部门名称、上下级 |
| ★3 | 人员名单 | 姓名、登录账号、部门、手机、**岗位角色**（ADMIN 管理员 / HANDLER 办案员 / LEGAL 法制审核 / LEADER 负责人；一人可多角色）。谁是"负责人"决定谁能批立案、延期、作决定、结案 |
| ★4 | 执法证台账 | 姓名、执法证号、部门、有效期至、**是否具法律职业资格**（法制审核岗必须）。立案时校验两名持证办案人员，证不在台账或过期立不了案 |
| 5 | 委托执法档案 | 如有委托：受托单位、委托书文号、委托事项、有效期（须公布） |
| 6 | 存量案件 | 是否要把在办/历史案件导入。若要，提供案件台账 Excel（案号、当事人、案由、立案日、状态、承办人）；已结案件建议不导，线下归档 |

## 四、正式文本（法制科）

系统里这几类是骨架和占位，必须换成局方正式文本才能出正式文书。

| # | 材料 | 现状 | 提供形式 |
|---|---|---|---|
| ★1 | 裁量基准 | 8 档骨架 | 局正式裁量基准文件（含每档对应的从轻/减轻/从重情形与幅度） |
| ★2 | 法律依据条文 | 常用条款种子，需校核 | 按正式文本逐条校核（法名、条款号、条文原文） |
| ★3 | 文书模板正文（14 类） | 骨架，含 {{占位符}} | 告知书、决定书、调查终结报告、结案报告、催告书、中止/恢复、终止决定、先行登记保存决定书、封存决定书、责令改正通知书、协查函、移送函、受案回执——按局方现行格式提供 Word 版；管理员在「文书模板」页粘贴维护 |
| ★4 | 案由字典校核 | 35 项（依苏医保督〔2024〕1号） | 法制科按本地执法事项清单增删（辽宁 2024 清单 13 项已内置） |
| 5 | 签章方式 | 支持可配置签章网关，默认保留模拟签章 | 提供 CA 供应商文档、联调地址和凭证，确认签署授权及验签样本 |
| 6 | 2027 年节假日 | 待国办通知（通常 11 月） | 通知发布后管理员在「节假日表」批量录入，含调休上班日 |

## 六、上线前验收（业务科室，1–2 天）

| # | 事项 | 说明 |
|---|---|---|
| ★1 | 真实办案员全流程试办 | 用浏览器从线索登记走到结案归档办一件完整案子（含告知、陈述申辩、法制审核、集体讨论、决定、送达、执行、结案）。这是唯一能发现"按钮不出现、回填不对"这类问题的手段 |
| ★2 | 案卷比对 | 拿一件近期真实结案的纸质案卷，与系统卷内目录、合成打印逐项比对，确认缺项与顺序 |
| 3 | 文书样张确认 | 用正式模板生成告知书、决定书各一份，法制科确认格式与措辞 |
| 4 | 督办/工作台口径确认 | 负责人看一遍督办看板 17 类预警与工作台，确认口径符合局内习惯 |
| 5 | 首次登录 | 每位用户首次登录须改密，请安排在培训现场完成 |

## 七、上线当天顺序（供参考）

空库首启（`.env` 三个秘密值）→ 审核机构目录并开通正式人员账号 → 预检并导入执法证 → 参数按第三节确认值设定 → 文书模板/裁量基准/法律依据换正式文本 → 节假日表核对 → 健康巡检与备份 crontab 装好并试跑 → 用户培训并首次登录改密 → 正式启用。
