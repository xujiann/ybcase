# 三阶段功能使用说明（2026年11月7日）

本说明覆盖本轮新增的执行续办与救济结果、报表补录纠错与冻结版本、财政核对与外部网关就绪检查，以及旧机构核对归类。实际发布版本、测试和上线结论以本次发布记录为准。

## 1. 账号与办理分工

| 账号类别 | 日常用途 | 本轮主要入口 |
| --- | --- | --- |
| 区市县 `DISTRICT` | 办理本机构范围内的案件，提交后续事实和补录申请 | 案件详情“执行续办与救济结果”“历史报表缺项补录”“报表补录纠错” |
| 局机关处室 `BUREAU` | 依法定岗位查看、复核、汇总和导出 | 统计分析的三张报表、补录审核、报表预览与冻结版本 |
| 医保中心 `AGENCY` | 办理分派的协议处理，登记实际约谈 | 独立协议处理入口；不使用行政案件续办及全局报表入口 |
| 管理员岗位 `ADMIN` | 维护正式账号、机构和集成配置检查 | 用户管理、机构管理、集成工作台 |

账号类别、所属机构和业务岗位分别设置。局机关全局报表要求 `BUREAU` 类别并具有法制、负责人或管理员岗位。冻结批次确认要求另一名局机关法制或负责人，且所属处室已启用；只有管理员岗位不能确认。续办、补录和财政核查的复核同样由服务端检查当前岗位、机构范围及申请人与复核人是否不同。

页面按钮只提供操作入口。账号停用、归属变更、岗位变更或来源数据变化后，提交可能被拒绝，须刷新核对。

## 2. 基层账号：日常录入与决定后的续办

### 2.1 日常办案直接形成报表来源

1. 立案时核对机构编码、性质、等级及当事人信息；系统保留案件所属机构。
2. 调查终结时确认违法发生起止日期、认定事实和认定金额。
3. 作出处罚决定时录入处罚依据、决定内容及各类金额。
4. 登记实际缴款、送达、协议处理、检查和约谈结果。各报表按各自业务日期取数，不另填汇总表。

历史原卷确实缺少报表所需字段时，在案件详情的“历史报表缺项补录”中选择仍缺失的适用字段，填写真实值、申请理由和材料出处，提交另一人复核。零金额属于有效值，不能当作缺失覆盖。未批准的申请不进入报表。

### 2.2 执行续记、冲正和实际退款

作出处理决定后，打开案件详情“执行续办与救济结果”。页面同时展示原状态、原卷号、有效决定、款项余额、执行记录及申请历史。已结案、已归档案件的后续事实独立登记，原案件和原卷保留。

- **申请执行续记**：选择罚款、退回基金、没收或加处罚款，填写实际到账金额、日期、凭证号和方式，并填写理由及材料出处。提交后等待另一人复核。
- **加处罚款**：除实际到账金额外，按正式材料填写人工核定总额和核定文号／按日依据。系统不把罚款本金自动当作核定金额。
- **申请整笔差错冲正**：关联一笔错误登记的正向执行记录，填写冲正生效日和凭证。批准后以负向记录完整抵销，原记录仍保留。
- **登记实际退款**：关联原款，填写本次实际退付金额、日期和真实退款凭证。可以登记部分、分次实际退付；系统校验可退余额，不自动发起付款。

冲正用于登记差错；退款用于真实资金退付。已发生退款的来源不能再整笔冲正。不得为修正报表而虚构执行记录。

页面“业务截至日”用于查看历史核对结果；新申请仍以当前有效资料和材料进行复核。同案有待复核申请时，须先处理或撤回，再提交下一项。

### 2.3 法院后续申请与回执

1. 在“登记法院后续申请”中填写本轮实际申请日期、申请文号及补正／再次申请依据。
2. 另一人核对通过后形成独立申请轮次。
3. 收到法院结果后，选择相应轮次，在“登记本轮法院回执”中填实际受理、退回补正或不予受理结果，以及日期、文号，再提交复核。

这些记录用于反映实际办理事实；平台不会替办案人员自动提交法院申请。

### 2.4 救济与决定更正

1. 先“登记救济／更正受理”，选择行政复议、行政诉讼或决定更正，填写受理日期、文号、理由及材料出处。
2. 收到结果后“提交结果材料”，关联受理记录，人工确认维持、文字更正、变更或撤销及生效日期。
3. 非维持结果按结果文书填写完整的有效决定类型、文号、金额、依据和正文，交另一人复核。

批准后形成独立有效决定版本。原决定、原文书和已归档案卷不回写。撤销版本不列入相应截至日的处罚人口；变更版本按有效金额及依据取数。退款、重新送达等实际后续事项仍须分别办理，不因结果登记自动完成。

公示导出按上海当日和本次取数时已批准的信息判断：已有生效的独立决定版本时，原公示条目不再导出；未来尚未生效、未批准的版本不提前影响原公示。原决定的公示和撤回标记保留，新版本不会自动公示，原决定公示入口也不能用于再次公开已被有效版本替代的原决定。相关人员须根据结果材料另行核对公示办理。

## 3. 局机关账号：三张报表与正式批次

### 3.1 现有 Excel 导出

打开“统计分析”，按以下入口操作：

| 报表 | 选择条件 | 取数范围 |
| --- | --- | --- |
| 行政处罚情况统计表 | 年度、决定起止日、执行截至日；也保留“导出2024–2026年原表” | 按原决定日期选取处罚记录，按业务截至日核对有效决定及已批准执行净额 |
| 基金监管部门执法人员办理案件情况统计表 | 统计开始日、统计截止日 | 期间在办、已办结机构案件，以及尚未转案件的已完成检查等业务事实 |
| 医保部门约谈定点医药机构台账 | 年度、实际约谈起始日、统计截至日 | 实际已登记约谈；协议处理的“拟约谈”或未登记实际约谈不替代台账记录 |

处罚表的“导出内部核对版”沿用已有年度字段，附内部对账说明；正式上报格式仍须由业务处室确认。保存冻结批次不会把内部核对模板变成另一套官方模板。2024–2026年原表入口继续保留。

“缺项检查”与年度处罚导出使用同一人口及日期条件。历史未登记、无法核实或不适用的值保持空白，不自动补造。处罚本金、加处罚款和退回基金分别核算。年度处罚内部对账页另列本表三类款项正向收缴、冲正／退付和净入账合计，原表外观不增设退款列。

每次直接导出按当前可用资料重新生成，不自动形成正式批次。

驾驶舱与旧月报金额同样使用上海当日的有效决定和已批准执行净额。月报仍按原决定日期、实际到账／退款日期归月，退款月可显示负数；案件状态、立案和结案计数仍依据原案件记录及当前账号可见范围。其“收缴合计”等汇总与处罚表分列的金额须按相同款项类别核对，不能把加处罚款或没收混作罚款本金。

### 3.2 生成、预览、确认和原样下载

在“报表预览与冻结版本”中：

1. 选择三张报表之一，填写业务期间及业务截至日；执法人员表的截至日与统计结束日一致。
2. 点击“生成待确认版本”。系统在同一数据快照内生成真实 Excel 文件并保存原始字节、文件 SHA-256、模板版本及摘要、口径版本、取数时点、生成者和逐行来源。
3. 点击“预览／核对”，分页查看冻结行；来源显示对应案号／登记来源及工作表行号，可进入有权访问的业务页面核对。来源页面继续执行原有权限检查。
4. 核对人可原样下载文件。另一名局机关法制或负责人填写确认意见，点击“确认冻结批次”。生成者不能确认自己的批次。
5. 确认后状态为“已确认”。再次下载返回已保存的同一份 Excel 字节，不因业务资料后来改变而重算；页面核验下载文件 SHA-256。

待确认版本也允许预览和原样下载，状态会明确显示。确认保存的是该批次文件及核对结论；不代表系统代替业务人员确认上报审批手续。

列表、预览和差异均分页；服务端限制页大小、单次行数、文本和文件容量，并控制并行生成数。超限时按业务范围缩小期间分批生成。

网络失败后可在同一页面重试生成，页面保留原生成请求号。相同账号、相同请求号和相同参数的顺序重试返回原批次；并发首次提交发生请求号冲突时，返回可重试提示（业务码2193），保留原请求号重试。不会保存两份相同请求的批次。

### 3.3 截至日与更正重报

默认口径为“**按业务日期＋生成时已批准的信息**”：业务发生／生效日期须不晚于业务截至日，独立后续记录须在本次取数时点已批准。未批准、未来生效或未来到账的记录不进入相应结果。

例如，上月发生的真实到账今天才完成续记复核，可以进入今天生成的上月更正重报；上月原冻结文件仍保持原样。

对已确认批次点击“更正重报”，沿用同一报表类型、期间及业务截至日，生成新批次并关联前版。预览“与前版差异”查看新增、移出和字段更正，再由另一人确认。新批次不覆盖前版，也不允许把不同期间的报表冒充同一期间的更正版。

### 3.4 已批准补录值录错后的纠错

基层在案件详情“报表补录纠错”中，只能选择原业务值缺失、且已有已批准报表补录值的字段。填写新值、纠错理由和原始材料出处后提交。局机关法制或负责人可在案件内或统计分析纠错审核队列复核。

复核时核对原业务快照、当前报表值、本次拟更正值及来源。申请人不能自审；来源资料或申请人归属变化时，须驳回后重新申请。批准前报表继续使用旧批准值；批准后使用新批准值。旧申请、旧值、理由、材料出处和复核记录均保留。原有非缺失业务值不通过报表补录纠错覆盖。

纠错批准后如需更正已报报表，须按上节生成关联前版的新批次；旧文件不会自行替换。

## 4. 管理员：正式机构和账号核对归类

### 4.1 旧机构归类

1. 进入“机构管理”，筛选“待归类”，对照局方确认的正式机构名单和职责文件。
2. 点击“核对归类”，选择处室 `BUREAU`、分局 `DISTRICT` 或医保中心 `AGENCY`。
3. 查看机构编码、所属账号和类别冲突。存在不同类别账号时，先在用户管理逐项核实，重新预览后再提交。
4. 填写归类理由和局方核对依据，确认归类。预览后机构或所属账号有变化时，系统拒绝旧预览，须重新核对。

归类保留原机构ID和原业务归属，不重建机构、不迁移历史案件。成功后类别固定，不能反复切换。该操作不会顺带替所有所属账号设置类别、改密码或改岗位。

### 4.2 正式账号分类与名单导入

在“用户管理”逐个核对真实姓名、登录账号、所属单位／处室、账号类别、岗位和启停状态。类别与已归类机构须一致：区市县办案人员使用 `DISTRICT`，局机关处室使用 `BUREAU`，医保中心经办使用 `AGENCY`；AGENCY使用其专用岗位。

正式名册较多时可“批量导入账号名册”，先预览新增／更新／错误记录，核对后再应用。不要把样例或模拟名单当作正式名单应用。机构归类与账号归类是分别核对的步骤；未确认的历史归属不自动推断。

## 5. 财政核对与外部网关边界

集成工作台可选择已登记的原执行或已批准续记，建立财政核对批次，分组运行核对并重试失败项。差异经分派后由承办人填写核查说明及凭据，再由另一名法制或负责人复核。核对结果、当次外部值和处理过程保留历史。

财政核对不会直接新增到账、冲正或退款。需要纠正资金登记时，按案件内的独立续办申请办理。

管理员“网关就绪检查”显示监控、签章、财政、电子送达的启用、地址及凭据配置状态，并可调用约定的 `health/check` 做探测。就绪标志或健康探测通过，只说明相应配置／探测结果，不等于供应商正式业务联调完成。

目前未提供真实供应商接口资料与正式凭据时，只能按模拟接口清单和人工复核流程验收。真实接入仍需局方及供应商确认协议、认证、测试环境、字段和错误码、签名／回执规范、幂等与重试约定及业务验收。不要据此宣称财政到账、正式电子送达或电子签章已在真实供应商侧打通。

电子回执服务账号与超时检查分别配置；自动超时检查默认关闭。监控取数也须具备真实网关配置后再运行。人工核定的金额、法律结论和实际办理事实由有权人员核实、批准。

## 6. 验收操作清单

在独立验收环境准备基层承办人、另一名局机关法制／负责人、管理员和经办账号，使用明确标注的测试案件及材料：

- 基层完成立案机构信息、调查确认字段和处罚依据，局机关直接导出三张相应报表；确认未完成实际约谈不会自动出现台账行。
- 对决定后案件提交一笔执行续记，批准前不入账，批准后按实际到账日期纳入；核对本金、加处罚款、退回基金的分别计算。
- 对错误登记整笔冲正，对实际退付登记部分退款；核对原记录保留、不能超额、净额和对账说明一致。
- 登记法院申请及回执轮次，核对原卷不变；登记救济结果并复核，核对有效决定及撤销后的报表人口。
- 补录一项历史缺失字段并批准，再提出纠错；核对批准前后取数差异、原业务值及旧来源记录保留，零值不能被覆盖。
- 生成三种冻结版本，预览分页与来源，原样下载；生成者自确认、纯管理员确认和跨类别访问应被拒绝。
- 由另一名有权业务人员确认批次；改变业务资料后重下载旧批次，核对文件摘要不变；关联前版生成更正重报，查看行级差异。
- 以旧截至日核对今天批准的历史到账，确认原冻结版保持原样；未来到账、未来生效、待审核记录不进入当次结果。
- 管理员先预览旧机构归类，核实账号冲突并填写依据；确认机构ID、账号凭据、岗位和既有业务归属未因机构归类改变。
- 使用模拟网关检查批次差异分派、核查、另一人复核和失败重试；分别记录配置就绪、模拟通过、真实业务未联调状态。

## 7. 主要接口（供运维核对）

| 用途 | 接口 |
| --- | --- |
| 后续事实与有效值 | `GET /api/bureau/cases/{caseId}/continuations?cutoff=YYYY-MM-DD` |
| 登记救济受理／提交续办申请 | `POST /api/bureau/cases/{caseId}/continuations/remedies`、`/requests` |
| 续办复核／撤回 | `POST /api/bureau/cases/{caseId}/continuations/requests/{id}/review`、`/cancel` |
| 三张现有Excel导出 | `GET /api/bureau/stats/penalties/download`、`/enforcement-work/download`、`/interviews/download` |
| 补录纠错状态／申请 | `GET/POST /api/bureau/cases/{caseId}/report-supplement-corrections` |
| 补录纠错队列 | `GET /api/bureau/report-supplement-corrections/pending` |
| 补录／纠错复核 | `POST /api/bureau/cases/{caseId}/report-supplements/{requestId}/review` |
| 报表批次列表／生成 | `GET/POST /api/bureau/report-versions/batches` |
| 批次详情、行、差异、确认、原文件 | `GET /api/bureau/report-versions/batches/{id}`、`GET .../{id}/rows`、`GET .../{id}/changes`、`POST .../{id}/confirm`、`GET .../{id}/download` |
| 机构核对预览／确认 | `GET /api/system/depts/{id}/classification-preview?orgKind=BUREAU`、`POST /api/system/depts/{id}/classification` |
| 账号名册预览／应用 | `POST /api/system/users/roster/preview`、`/roster/apply` |
| 网关配置状态／探测 | `GET /api/bureau/integrations/readiness`、`POST /api/bureau/integrations/probe/{target}` |
| 财政核对批次 | `GET/POST /api/bureau/integrations/treasury/batches`；批次运行、条目重试／分派／核查／复核使用相应子接口 |

批次类型为 `PENALTIES`、`ENFORCEMENT_WORK`、`INTERVIEWS`；生成请求带唯一 `requestKey`，更正重报带 `parentBatchId`。冻结接口返回禁止缓存头，原文件下载同时返回 `X-Content-SHA256`。维护工具也须使用正常账号授权，不得绕过复核或直接更新原业务表。
