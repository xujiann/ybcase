# 外部网关联调验收清单

当前没有供应商地址、真实凭据和业务样本。本轮完成可配置接口、隔离 PostgreSQL 与模拟供应商验证，以及下面的真实联调清单；不能据此认定财政、电子送达、监控或真实签章供应商已经验收。

## 配置与账号

配置由部署人员通过环境或受控配置文件维护，不通过业务页面填写口令。页面「案件查办 → 对账与接口」只显示是否启用、地址格式及凭据是否已配置，不返回地址和令牌。

| 配置项 | 用途与默认值 |
| --- | --- |
| `ybcase.integration.{target}.enabled` | 明确设为 `true` 才启用；未配置不启用。target 为 `monitor`、`signature`、`treasury`、`delivery`。 |
| `ybcase.integration.{target}.url` | 供应商基础 URL。正式环境要求 HTTPS；仅本机联调允许 localhost/127.0.0.1 HTTP。不跟随重定向。 |
| `ybcase.integration.{target}.token` | 出站 Bearer 凭据，通过受控渠道交付、轮换，不放入源码、截图或验收报告。 |
| `ybcase.integration.delivery.callback-username` | 电子回执专用平台登录账号，必须精确匹配当前启用账号。 |
| `ybcase.integration.delivery.receipt-timeout-hours` | 回执等待小时数，默认 168，允许 1–720。 |
| `ybcase.integration.delivery.timeout-scan-enabled` | 自动超时扫描，默认关闭。上线需明确决定是否启用。 |
| `ybcase.integration.delivery.timeout-scan-ms` | 超时扫描间隔，默认 60000 毫秒。 |
| `delivery_electronic_decision_allowed`（平台业务参数） | 决定书电子送达只在此参数明确为 true 时允许；缺失或禁用均拒绝。 |

例如 `ybcase.integration.delivery.callback-username` 可由环境变量 `YBCASE_INTEGRATION_DELIVERY_CALLBACK_USERNAME` 提供。配置检查通过只说明配置满足格式要求；实际可达性和业务能力须继续验收。

回执账号只授 `INTEGRATION` 专用角色，不兼任办案、法制、负责人或管理员。迁移仅建立该角色，不自动建立或授权正式用户。通过正常登录取得有效 JWT；停用、令牌版本变化、账号不匹配、混合角色或无专用角色时不得接收回执。回执接口不允许匿名访问。

## 出站 HTTP 契约

统一使用 JSON POST，`Authorization: Bearer <供应商凭据>`；连接超时 3 秒、读取超时 8 秒、响应上限 1 MiB。不自动重试业务发送，不记录响应正文或凭据。

| 相对路径 | 请求与响应 |
| --- | --- |
| `health/check` | 请求 `{"probe":true}`；成功须返回 `{"ready":true}`。这是无业务效果的约定探测，不能替代缴款、送达和签章验收。 |
| `receipts/lookup` | 请求 `{"receiptNo":"票据号"}`。找到返回 `{"status":"FOUND","receiptNo":"同一票据号","amount":23.45,"paidDate":"2026-11-07","paid":true}`；未找到返回 `{"status":"NOT_FOUND"}`。金额必须为非负 JSON 数值且保持精确值；数值精度最多 38 位、小数位最多 24 位。 |
| `deliveries/send` | 请求包含 `deliveryId`、`documentId`、`contentHash`、`title`、`content`、`receiver`、`channel`。请求头携带稳定的 `Idempotency-Key`。成功返回 `{"status":"ACCEPTED","providerId":"供应商发送编号"}`。同一幂等键必须返回同一发送编号、不能重复实际发送。 |

监控拉取和签章沿平台既有 `clues/pull`、`signatures/sign`、`signatures/verify` 契约分别验收；本轮未新增自动监控拉取任务。签章需验证真实证书身份和有效性，不能把模拟签名当成正式 CA 签章。

## 财政对账验收

平台入口为 `GET /api/bureau/integrations/treasury/sources`；按当前案件权限先筛选，再分页，覆盖原执行记录与已经批准的有效续登记正数缴款，冲正负数不作为第二笔缴款核验。

1. `POST /api/bureau/integrations/treasury/batches` 提交 `{requestKey,executions:[{source:"ORIGINAL"或"CONTINUATION",id}]}`，每批 1–100 条；同账号同请求号同来源只建立一个批次。批次保存本地票据、款项类型、金额和缴款日期快照。
2. `POST /api/bureau/integrations/treasury/batches/{id}/run` 每次最多核对 10 条，逐条提交结果。断线或进程中断后先刷新批次，再继续处理剩余项；不得仅因浏览器超时重复生成缴款。
3. 检查金额、日期和已缴清状态全部一致；分别验证不一致、缺票号、未找到、未配置、超时、错误响应和源数据变化。每次财政金额、日期及核对结果留历史快照，重试不抹去前次证据。
4. 差异由监督岗位调用 `items/{id}/assign` 分派；承办人经 `investigate` 提交说明与凭据；另一名法制或负责人通过 `review` 复核或退回。管理员单独岗位不能代替复核人。
5. `items/{id}/retry` 可对尚未提交复核的差异发起重新核对。待复核和已复核记录不直接重跑；新核对可以建立新批次。

对账默认只核对，不自动入账、退款或冲正。确需更新业务结果时，按救济/后续执行申请与另一人复核流程办理，引用批次和条目编号；原决定、原执行行和封存卷宗保留。

## 电子送达与回执验收

人工从案件详情发起。必须已经登记同意书、结构化受送达人和同意地址；历史自由文本不推测回填。只允许支持的具体文书类型，决定书须处于已决定未送达阶段且当前业务参数明确允许。封卷、文书内容或同意地址变化时，不能继续使用旧发送草稿。

- 创建与发送：`POST /api/bureau/cases/{caseId}/electronic-deliveries`，正文 `{documentId,requestKey}`；随后人工调用 `.../{id}/send`。供应商仅受理不代表已经送达。
- 回执：`POST /api/integrations/delivery/receipts`，请求头为专用账号平台 JWT，正文 `{deliveryId,providerId,eventId,status,occurredAt,receiptNo}`。状态支持 `DELIVERED`、`REJECTED`、`FAILED`、`TIMED_OUT`；时间须含时区，签收必须有回证编号。
- 同一事件编号同一内容重放应返回原结果；同一事件编号内容改变应拒绝，不覆盖旧证据。发送编号必须与供应商编号相符。
- 保留 5 分钟时钟容差，但转换到上海业务日期后不得认定明天已经签收。验证午夜前后时间边界，不修改服务器时钟做测试。
- 有效签收再次复核当前规则、同意地址、文书指纹与封卷状态后，才关联原文书、登记回证；决定书签收可推进送达状态。无效、禁用、封卷或内容不一致只保存拒绝事件，不改变案卷。
- 拒收、失败与超时不认定送达；自动超时扫描有事务锁、每次最多 100 条，默认关闭。晚到的合法回执仍须重新经过全部条件检查。

必须覆盖账号停用/令牌过期、错误服务账号、无专用角色、供应商编号串用、事件冲突重放、断线重试、规则刚禁用或缺失、地址改变、文书改变、封卷、拒收、超时及晚到回执。核对同一签收仅有一条实际送达记录及对应回证文书。

## 真实验收交付物

供应商需提供测试环境、受控凭据、接口版本及负责人、幂等保留期限、回执时间/票号规则、失败重放办法、真实脱敏样本和可核验的票据/送达/证书记录。局方与供应商共同留存测试用例、请求编号、供应商编号、预期和实际结果；报告去除姓名、地址、令牌及业务正文。

先验证配置与探测，再对真实样本逐项验收权限、业务一致性、重复与故障恢复，最后决定是否启用对应网关。模拟测试证据保存在项目 `data/recovery/three-stage-delivery-20261107/`；真实供应商联调当前未完成。
