# 发布与恢复操作说明

发布统一使用已测试候选包和 `release.py`。旧 `upgrade.sh`、`server-build.sh` 只代理明确的候选目录激活；不再支持覆盖产物后只看健康 UP 的快捷发布。`push-update.sh` 仅上传并建立隔离演练，不直接切正式服务。

## 候选包与测试门禁

在完整回归及生产构建完成后，用 `package-release.py` 打包 JAR、前端与运维工具。输出目录必须新建且位于项目内，不能放在 OneDrive。声明的目标版本须等于 JAR 内实际迁移最大版本；已执行迁移保持原样。

```powershell
python deploy/package-release.py --jar server/target/ybcase-server-1.2.0.jar --dist frontend/dist --output data/recovery/本次发布/candidate --baseline-schema 50 --target-schema 实际目标版本 --baseline-jar-sha256 实际旧JAR摘要 --baseline-index-sha256 实际旧首页摘要
```

候选目录包含 `payload.tar.gz`、逐文件 `manifest.json`、`release-config.json`、执行用 `release.py` 和 `data-audit.py`。不包含 `.env`、密码或真实凭据。基线必须来自本次生产只读核对；配置在 prepare 后不能改变。

将候选放到 `/opt/ybcase/releases/本次标识`，以该目录中的同版本工具执行：

```bash
python3 /opt/ybcase/releases/本次标识/release.py --release-dir /opt/ybcase/releases/本次标识 prepare
```

prepare 保存原产物、数据库及附件备份，建立有随机名称和所有权标记的克隆库及无宿主端口的 pilot，实际恢复并升级，核对旧字段行、账号角色及资源身份。后续非空跨账号和导出验收在该 pilot 中进行。

激活前在候选私有目录写入以下 JSON 门禁。所有 `jarSha256`、`indexSha256` 必须与同一候选匹配；数值为实际成功结果，不能填计划值。

| 文件 | 必需字段 |
| --- | --- |
| `tests.passed` | `passed:true`、`backendTests` 正整数、`frontendTests` 正整数、`buildPassed:true`、两产物摘要 |
| `pilot.passed` | `passed:true`、本次实际 `pilotId`、`checksPassed` 正整数、两产物摘要 |
| `git.json` | `pushed:true`、已核验远端的完整 `commit`、两产物摘要 |

## 激活与连接中断恢复

```bash
python3 /opt/ybcase/releases/本次标识/release.py --release-dir /opt/ybcase/releases/本次标识 activate
```

工具核对基线、账号、配置、原容器和附件卷后暂停原 Caddy，再停止应用，保存冻结一致性恢复点。仅重建 app；新库版本、健康、旧行、账号和附件核对全部通过后才恢复流量。现有数据库、Caddy、附件卷及 `.env` 保留。已有旧静态资源保留供未关闭的页面使用。

恢复流量的动作位于自动数据库回滚处理之外。SSH 断线或响应丢失时，先查本次私有 `state.json`、完成标记和实际服务，不能重复 activate，也不能按连接失败推定需要恢复旧数据库。

```bash
python3 /opt/ybcase/releases/本次标识/release.py --release-dir /opt/ybcase/releases/本次标识 status
python3 /opt/ybcase/releases/本次标识/release.py --release-dir /opt/ybcase/releases/本次标识 resume
```

resume 仅对已通过完整激活核验、身份及产物一致的候选核对流量状态，绝不恢复数据库。`PAUSE_INTENT` 等不确定所有权状态须先人工核实，工具不会盲目切换暂停。可能已经放行流量后，禁止自动用旧快照覆盖用户新写入。

公网及实际浏览器验收通过后运行 final，再 cleanup。cleanup 只清理记录中身份一致的本次 pilot 和克隆库，发布备份及证据保留。

## 日常完整备份

安装新脚本后立即正常运行一次 `backup.sh`，建立完整集合，再验证健康检查；旧 loose dump 不会被猜测为新完整集合。

```bash
bash /opt/ybcase/backup.sh
python3 /opt/ybcase/backup-set.py check --directory /opt/ybcase/backup
```

每套包含数据库、需要时的附件包、`files-时间标识.json` 引用清单及 `set-时间标识.json`，记录同批次文件大小和 SHA，并逐项核对数据库引用的 FILE 路径和大小，不能靠孤儿文件凑足数量。只有全部成功后才原子提交完整标记及 `last-success.json`；`last-attempt.json` 单独记录最近尝试。最近尝试失败会立即使健康检查失败，即使旧成功集尚未过期。运行中超过两小时也视为停滞。默认保留最新 14 套完整集合，不猜测删除旧无清单文件。

健康检查同时验证完整文件及摘要、最近结果与新鲜度。文件较大时须把校验 I/O 纳入容量观测，不能以关闭完整性校验代替解决磁盘瓶颈。

## 受控加密外拷及导入

`backup-transfer.py` 使用运维已安装的 age 和受控公钥文件。公钥加密及解密参数依据 [age 官方说明](https://github.com/FiloSottile/age#usage)；私钥在恢复端保管，不写入脚本、命令日志或配置仓库。

```bash
python3 deploy/backup-transfer.py export --manifest /opt/ybcase/backup/set-实际标识.json --recipients /受控位置/recipients.txt --destination /已挂载的备份目标
python3 deploy/backup-transfer.py import --encrypted /备份目标/backup-实际标识.tar.age --receipt /备份目标/backup-实际标识.tar.age.receipt.json --identity /受控位置/identity.txt --destination /全新私有导入目录
```

导出只接受完整集，密文和回执不覆盖现有文件；导入核对受控保存的回执摘要、解密认证、清单及成员摘要，拒绝路径穿越、链接和额外文件，失败不提交导入目录。回执需由运维受控保存，不能把同一来源不明副本的自报摘要当作可信来源。

导出到目录、加密通过或解密导入通过，均不等于已经完成异地备份验收。实际 NAS／异地主机、密钥管理及恢复窗口由局方确认。

## 独立恢复演练

```bash
python3 deploy/restore-rehearsal.py restore --manifest /全新私有导入目录/set-实际标识.json --work-directory /全新恢复工作目录 --baseline /一致性备份时的原字段摘要.json
python3 deploy/restore-rehearsal.py cleanup --work-directory /同一恢复工作目录
```

默认使用当前 Docker Compose 的 db，也支持 `--transport native --host 127.0.0.1 --port 5432 --user hip`；native 口令仅从环境读取。工具只新建 `ybcase_restore_drill_随机值`，以 OID、属主及随机注释记录身份，原库不会被重建。恢复采用单事务，输出全表摘要和附件库存；提供 baseline 时严格比较原字段行，未提供时明确标记未作源行对照。cleanup 必须身份一致且无活动连接，不强制踢连接，保留证据及恢复文件。

## 容量验收

`tools/capacity-check.py` 仅用于隔离、非空夹具的只读及报表混合负载。必须提供一小时内核对的 `isolation-proof.json`，含 `isolated:true`、精确 `baseUrl`、独立 `database`、JAR SHA、`caseCount` 及 `checkedAtEpoch`。默认应用端口 8090、公网地址和非白名单路径均拒绝。

```bash
python3 tools/capacity-check.py --base-url http://127.0.0.1:隔离端口/api --isolation-proof isolation-proof.json --paths read-paths.json --output capacity-result.json --workers 4 --requests 100 --p95-ms 5000 --max-error-rate 0
```

令牌仅从 `YBCASE_LOAD_TOKEN` 读取。路径文件为 JSON 数组，可混合案件、工作台、统计及三张下载路径；实际 XLSX 验证 ZIP 完整性。结果保存输入目标、实际 P95、错误率和吞吐量，并按目标返回成败。示例目标和合成夹具用于工具验收，不能替代局方确认的机构数、真实案件量、附件上传、集中冻结及慢网关组合验收。

## 模拟与正式运行模式

`YBCASE_RUNTIME_MODE` 默认为 `SIMULATION`，页面持续显示模拟性质；正式启用设置为 `FORMAL` 后，新签章必须使用配置的 CA，电子回证须满足正式证据校验。旧 MOCK 记录仍可检查摘要，但始终标记模拟，不能因切换运行模式而升级为正式签章。文书原有 signed 标记包含人工签名确认语义，不据该布尔值推定 CA 有效。

真实供应商、正式账号、2027 年日历和异地主机未提供时，完成的是可配置能力、模拟及隔离验收，真实投用验收保持待资料落实。
