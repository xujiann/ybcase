# ybcase 香港试运行 · 上线清单

服务器：腾讯云轻量 · 中国香港 · `43.129.201.125` · Ubuntu · 2C2G
访问方式：`https://43.129.201.125.sslip.io`（sslip.io 免域名 HTTPS）

> 全程约 20 分钟。命令里的 `<用户名>` 一般是 `ubuntu`（腾讯云轻量默认可能是 `ubuntu` 或 `root`，以购买时设置为准）。

---

## 第 0 步：本机准备产物（Windows，仓库根目录）

```bash
mvn -q test package && npm test --prefix frontend && npm run build --prefix frontend
```

产出 `server/target/ybcase-server-1.2.0.jar` 和 `frontend/dist/`。
（当前 jar/dist 已是最新构建，如无改动可跳过重新构建。）
后端测试须显式指定独立测试数据库，禁止使用开发或云端业务库。使用已验收产物发布时运行 `bash deploy/push-update.sh --prebuilt`；发布包附带的 `SHA256SUMS` 可用 `sha256sum -c SHA256SUMS` 校验。

## 第 1 步：控制台放行端口（腾讯云轻量 → 防火墙）

只放行三条，其余全关：

| 协议端口 | 来源 | 用途 |
|---|---|---|
| TCP 80 | 全部 `0.0.0.0/0` | HTTP（Caddy 自动跳 HTTPS + 签证书用） |
| TCP 443 | 全部 `0.0.0.0/0` | HTTPS |
| TCP 22 | **仅你自己的公网 IP** | SSH |

数据库 5432、后端 8090 **不要**放行——它们只在容器内网可达。

## 第 2 步：上传产物到服务器

本机仓库根目录执行（把 `<用户名>` 换成实际值）：

```bash
scp server/target/ybcase-server-1.2.0.jar <用户名>@43.129.201.125:/tmp/ybcase-server.jar
scp -r frontend/dist deploy/docker-compose.yml deploy/Caddyfile deploy/env.example deploy/backup.sh deploy/upgrade.sh deploy/healthcheck.sh <用户名>@43.129.201.125:/tmp/
```

## 第 3 步：服务器上就位

SSH 登录后：

```bash
ssh <用户名>@43.129.201.125

sudo mkdir -p /opt/ybcase && sudo chown $USER /opt/ybcase
mv /tmp/ybcase-server.jar /tmp/dist /tmp/docker-compose.yml /tmp/Caddyfile /tmp/env.example /tmp/backup.sh /tmp/upgrade.sh /tmp/healthcheck.sh /opt/ybcase/
cd /opt/ybcase && cp env.example .env
```

## 第 4 步：填 .env（关键，只改两个随机值）

```bash
# 生成两个强随机值
echo "DB_PASSWORD=$(openssl rand -base64 24)"
echo "JWT_SECRET=$(openssl rand -base64 48)"
nano .env    # 把上面两行的值填进 DB_PASSWORD / JWT_SECRET；DEMO_DOMAIN 已是 43.129.201.125.sslip.io，不用改
```

⚠️ `JWT_SECRET` 必须改成真随机值——保持示例默认值时 pilot 会**拒绝启动**（这是有意的安全门禁）。
空库首次部署还必须设置 `ADMIN_INIT_PASSWORD` 为强初始口令；缺失或使用默认口令会拒绝初始化。升级既有库保留服务器原 `.env` 和账号凭据，不覆盖为模板值。

## 第 5 步：装 Docker 并启动

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker   # 免 sudo 用 docker
cd /opt/ybcase && docker compose up -d
docker compose logs -f app | grep -m1 Started    # 看到 Started 即后端就绪（首启自动建表+种子）
```

Caddy 首次会去 Let's Encrypt 签证书（几十秒）。完成后浏览器打开：

**https://43.129.201.125.sslip.io**

新库使用 `admin` 与 `.env` 中设置的初始口令登录并完成首次改密；pilot 只初始化管理员，不创建其他演示账号。既有库使用现有账号。

## 第 6 步：上线后 5 分钟加固（试运行也要做）

1. **完成管理员首次改密并创建必要人员**：本系统改密即吊销旧令牌，新账号首次登录同样必须改密。既有人员继续使用自己的账号。
2. **挂每日备份**：
   ```bash
   chmod +x /opt/ybcase/backup.sh
   ( crontab -l 2>/dev/null; echo "30 3 * * * /opt/ybcase/backup.sh >> /opt/ybcase/backup/backup.log 2>&1" ) | crontab -
   ```
   每天 03:30 备份到 `/opt/ybcase/backup/`，保留最近 14 份。
3. **造 1-2 个完整演示案件**（线索→立案→调查→告知→审核→决定→送达→执行→结案），比空库有说服力。

## 日常运维

**升级新版本（唯一推荐路径）**：代码 push 到 GitHub 后，在服务器执行
```bash
cd /opt/ybcase-src && git pull --ff-only && bash deploy/server-build.sh
```
它会：拉最新源码 → Docker 里构建 → **升级前备份** → 留回滚点 → **原子替换** jar（写 .new 再 mv，不碰运行中的文件）→ 原地更新 dist 内容 → 同步脚本与 compose/Caddyfile（Caddyfile 有变才热重载）→ 重建 app → 健康检查。
本机网络可达时也可 `bash deploy/push-update.sh`（本机测试构建后上传）；已完成测试的发布包使用 `--prebuilt`。上传路径也会同步 compose/Caddyfile、校验 compose、保存旧前端与配置到 `rollback/<时间>/` 并重载 Caddy。旧哈希资源保留供已打开的页面使用，新 `index.html` 最后切换。

升级命令在备份缺失/失败、回滚 JAR 缺失/为空或 app 重建失败时返回非零；不能将旧容器健康当作新版本成功。`--skip-backup` 只供已在替换产物前成功备份的发布脚本使用。首次部署走 compose 启动，不调用升级脚本。

> ⚠️ 不要再用 `scp 覆盖 jar → docker compose up -d`：jar 被运行中的容器 bind mount 且惰性读取，原地覆盖会让旧进程随机 ZipException；而 compose 配置未变根本不会重建容器，新 jar 不加载、Flyway 不迁移。

**回滚**（升级失败时，顺序不可颠倒）：
```bash
cd /opt/ybcase
sudo docker compose stop app caddy                      # 先停，否则在途写入会落进即将被 DROP 的表
sudo docker compose exec -T db pg_restore -U hip -d ybcase --clean --if-exists --single-transaction < backup/db-<STAMP>.dump
cp ybcase-server.jar.prev ybcase-server.jar
sudo docker compose up -d --force-recreate app
# FILE 模式：还原同一 STAMP 的附件包（dump 先于 tar 生成，取同一对）
sudo docker compose exec -T app tar -C /app/data -xf - < backup/att-<STAMP>.tar
sudo docker compose up -d
```
回滚点 `.prev` 由 server-build.sh / push-update.sh 在覆盖前留存；回滚到的 jar 若早于库里已应用的迁移，Flyway 会拒绝启动——所以库必须一起恢复到同一 STAMP。

**恢复/换机**（灾备演练用同一套命令；每季度至少做一次）：
```bash
cd /opt/ybcase && sudo docker compose up -d db
sudo docker compose exec -T db pg_restore -U hip -d ybcase --clean --if-exists --single-transaction < backup/db-<STAMP>.dump
sudo docker compose up -d app
sudo docker compose exec -T app tar -C /app/data -xf - < backup/att-<STAMP>.tar   # FILE 模式
sudo docker compose up -d
sudo docker compose exec -T app sh -c 'wget -qO- http://127.0.0.1:8090/actuator/health'   # 须回 "UP"
```

**备份**：`/opt/ybcase/backup.sh` 已挂 crontab 每日 03:30（`sudo crontab -l` 查看；只保留一条，勿重复），库与附件各保留 14 份于 `/opt/ybcase/backup/`。备份失败会以非零退出码阻断 server-build 部署——这是有意的。

**健康告警**：`/opt/ybcase/healthcheck.sh` 挂 crontab 每 5 分钟（`*/5 * * * * /opt/ybcase/healthcheck.sh >/dev/null 2>&1`），检查公网入口、容器健康端点、三个容器状态、磁盘（默认 85%）、昨夜备份是否成功（默认 30 小时内须有新 dump）。状态变化才告警（正常→异常、异常→恢复各一次，持续异常每 6 小时重复），流水在 `/opt/ybcase/healthcheck.log`。要推送到手机：在 `.env` 加 `ALERT_WEBHOOK=<企业微信/钉钉/飞书群机器人地址>` 与 `ALERT_WEBHOOK_TYPE=wecom|dingtalk|feishu`（不配则只写日志）。首次装好后可手动 `bash healthcheck.sh; tail -1 healthcheck.log` 验证。

**节假日表**：每年 11 月国办通知发布后，管理员在「系统管理 → 节假日表」按年批量录入（含调休上班日）。未录入时督办看板顶部红条、管理员每月一条站内消息、启动日志 WARN 三处提醒；在录入之前该年度工作日口径的期限只跳周末。

**空库首次启动（正式上线换新库时）**：pilot 下必须在 `.env` 里设 `ADMIN_INIT_PASSWORD`（见 env.example），否则拒绝启动；只会创建 `admin` 一个账号，**不再创建** banban/fazhi/juzhang 演示账号，首次登录强制改密。人员由管理员在「用户管理」里建，其初始口令同样首次登录强制修改。

## V42 发布演练与对外接口

使用经发布记录核对 SHA-256 的 V34 安装包及本次构建的候选 JAR。在本机 PostgreSQL 中运行下列命令，`PGPASSWORD` 通过环境变量设置。脚本仅创建和清理以 `ybcase_release_` 开头的随机命名库，演练数据均为合成数据。

```powershell
python tools/rehearse-platform-upgrade.py --previous <V34-JAR> --candidate server/target/ybcase-server-1.2.0.jar --temp-root "$env:USERPROFILE/Temp" --scale-rows 7500
```

演练包括备份数据库与附件、核对迁移前后既有记录、用管理员导出三张带数据的 Excel、恢复升级前备份并用 V34 重新启动。真实环境回滚须恢复同一时点的库和附件，并按上文操作顺序停应用。

外部网关通过 `YBCASE_INTEGRATION_{MONITOR|TREASURY|SIGNATURE}_{ENABLED|URL|TOKEN}` 配置。分别启用对应网关，URL 填 HTTPS 基地址，令牌由部署环境保管。联调用环回 HTTP。请求及响应采用 JSON，已配置的令牌通过 Bearer 认证发送。连接超时、非成功响应及无效响应返回业务错误，可由操作人员重试。

| 网关 | 请求与返回 | 平台处理 |
| --- | --- | --- |
| 智能监控 | `POST /clues/pull` 请求 `limit=500`。返回 `items`，逐条包含 `externalId`、`suspectName`、`suspectType`、`content` | 启用网关和系统参数 `monitor_feed_enabled` 后，局机关管理员或负责人在「线索管理」拉取。相同外部编号和内容重复拉取只登记一次，同编号内容冲突时整批拒收 |
| 财政票据 | `POST /receipts/lookup` 请求 `receiptNo`。返回 `status=NOT_FOUND` 或 `status=FOUND` 及 `receiptNo`、数值 `amount`、`paidDate`、布尔值 `paid` | 在案件执行记录核对票据。核对结果包含金额、日期和支付状态，执行台账由原登记流程维护 |
| 电子签章 | `POST /signatures/sign` 请求 `contentHash`、`signer`，返回相同摘要和签署人及 `signature`。验签 `POST /signatures/verify` 提交上述三个字段并读取布尔值 `valid` | 发送 UTF-8 内容的 SHA-256 摘要。签署人取当前操作账号，签署请求附 `Idempotency-Key`。历史 `MOCK` 记录仍走原验签规则 |

三个网关默认关闭。正式接入前，在局方联调环境校对字段映射、权限与凭证、异常响应、监控增量策略、票据差异及 CA 签名验签。供应商可在本表契约与其原生接口之间部署适配服务。

## 合规红线（必读）

- 此环境为**境外不备案**，**只放虚构/测试数据做功能试运行**。
- **不得录入真实参保人信息**——医保监管数据出境有法律限制，境外环境不满足等保要求。
- 要正式录真实数据试点，须换**大陆备案 + 等保合规**环境（政务云/医保专网）。
